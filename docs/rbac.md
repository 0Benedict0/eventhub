# Ролі та доступ

На відміну від TaskFlow (роль на проєкт), тут роль — глобальна властивість
користувача, обрана при реєстрації:

| Дія                                   | ATTENDEE | ORGANIZER |
|-----------------------------------------|:--------:|:---------:|
| Переглядати/шукати події                 | ✅        | ✅         |
| Бронювати квитки                         | ✅        | ❌         |
| Створювати події                         | ❌        | ✅         |
| Завантажувати обкладинку своєї події      | ❌        | ✅ (лише своєї) |
| Бачити список бронювань на свою подію     | ❌        | ✅ (лише своєї) |

Перевірка на backend — `@PreAuthorize("hasRole('ORGANIZER')")` на рівні
сервісного методу (`EventService.create`) + додаткова перевірка володіння
рядком (`getOwnedEvent` в `setCoverImage`) — сама по собі роль ORGANIZER не
дає права редагувати чужі події, потрібна перевірка `organizer.id == requester.id`.
